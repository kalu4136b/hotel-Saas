## 1. Executive Summary

This guide outlines all operational capabilities, user workflows, and state transitions available in the Hotel SaaS MVP. The application is completely functional, strictly multi-tenant, and connected to an enterprise MySQL database through NestJS REST APIs and a Next.js App Router user interface.

No mock data, placeholder arrays, or simulated figures exist anywhere in the codebase. Every dashboard statistic, receipt number, table status, and report figure is generated by live SQL queries and backend business logic.

## 2. Authentication & Multi-Tenant Onboarding Operations

### 2.1 Tenant Provisioning via Platform Administration (`/admin`)
- **Policy:** Public self-registration and third-party social auth (Google OAuth) are decommissioned. All tenant organizations and initial administrative credentials are provisioned strictly by Platform Administrators (Super Admin console at `/admin`).
- **Provisioning Parameters:**
  - Hotel / Business Name (e.g., `Novotel Phuket City Grand`)
  - Subdomain / Organization Code (e.g., `novotel`)
  - Subscription Plan & Modules (`LITE_OPERATIONS`, `HOSPITALITY_PRO`, `ENTERPRISE_SUITE`)
  - Administrator Full Name & Email
  - Admin Initial Password
  - Default Currency Code (e.g., `USD`, `THB`, `EUR`)
- **Automated Backend Actions:**
  1. Creates a row in `tenants` with active subscription status and module entitlements.
  2. Creates a primary branch in `properties` with specified currency and default tax rate.
  3. Provisions a default `pos_outlets` record ("Main Restaurant & Bar").
  4. Provisions initial dining tables and operational configurations.
  5. Hashes the password using `bcrypt` and creates the `TENANT_ADMIN` user in `users`.
  6. Commits an immutable audit log entry in `audit_logs`.

### 2.2 Secure Authentication (`/login`)
- **What it does:** Validates credentials against MySQL and generates a cryptographically signed JWT.
- **Workflow:**
  1. Accepts username (or email) and password.
  2. Verifies `isActive = true` (disabled accounts are blocked).
  3. Compares bcrypt password hash.
  4. Returns `accessToken`, user profile, tenant information, and property settings.
  5. Automatically redirects to `/dashboard`.

## 3. Cash Drawer & Shift Management Operations

### 3.1 Opening a Cash Shift (`POST /api/pos/shifts/open`)
- **Location:** Global Shift Drawer indicator in the sidebar navigation or header.
- **Workflow:**
  1. Cashier opens the POS drawer modal.
  2. Enters starting cash float (e.g., `$100.00`).
  3. System creates a shift session in `pos_shifts` marked as `OPEN`.
  4. Shift indicator updates across the application to active.

### 3.2 Closing a Cash Shift (`POST /api/pos/shifts/close`)
- **Workflow:**
  1. Cashier or Manager triggers "Close Shift".
  2. Inputs actual physical cash counted in drawer.
  3. System calculates expected cash:
     $$\text{Expected Cash} = \text{Starting Float} + \sum(\text{Cash Payments Received in Shift})$$
  4. Records cash over/short variance in the database and updates status to `CLOSED`.

## 4. Dining Room & Floor Management Operations

### 4.1 Floor Plan Overview (`/dashboard/tables`)
- Displays all tables configured for the property (`T-01` to `T-06`).
- Live state badges:
  - **Green (`AVAILABLE`):** Table is free and ready for new guests.
  - **Amber (`OCCUPIED`):** Table has an active, in-progress order.
  - **Blue (`BILLED`):** Bill has been printed; waiting for customer payment settlement.
- Shows table number, seating capacity (e.g., 2, 4, 6 seats), and active order link.

### 4.2 Automated Table Lifecycle:
- Selecting an available table on a new Dine-In order automatically marks it **`OCCUPIED`**.
- Generating a bill transitions the table to **`BILLED`**.
- Settling payment or voiding the order automatically returns the table to **`AVAILABLE`**.

## 5. POS Sales Terminal Operations (`/dashboard/pos`)

### 5.1 Taking an Order
1. **Order Type Selection:** Choose between `DINE_IN` (requires table selection) or `TAKEAWAY`.
2. **Guest Information:** Optionally enter guest count and customer name.
3. **Category Filtering & Search:**
   - Filter items by category tabs (All Items, Starters, Main Courses, Desserts, Beverages).
   - Real-time instant search by dish name or SKU.
4. **Cart Actions:**
   - Click any dish card to add to cart.
   - Adjust quantities with `+` and `-` controls.
   - Add custom kitchen notes per line item (e.g., "No onions", "Medium rare").
5. **Real-Time Tax & Total Calculation:**
   - Subtotal is computed instantly.
   - Tax is applied using property tax rate (e.g., 10%).
   - Total amount payable is calculated automatically.
6. **Order Placement (`POST /api/pos/orders`):**
   - Saves `orders` and `order_items` in MySQL.
   - Assigns official order number (e.g., `ORD-0001`).

## 6. Kitchen Operations & KDS Display (`/dashboard/kitchen`)

### 6.1 Kitchen Order Ticket (KOT) Dispatch
- When an order is placed from the POS terminal, clicking "Send to Kitchen" creates a KOT record in `kots` and line items in `kot_items`.
- KOT status initializes as `PENDING`.

### 6.2 Kitchen Display System (KDS) Station
- Designed for tablet or wall-mounted touchscreens in the kitchen.
- Orders appear as interactive order cards showing:
  - Order Number & Table Number
  - Elapsed preparation timer (e.g., "12 mins ago")
  - Item quantities and special preparation instructions
- **Kitchen Actions:**
  - Click **"Start Cooking"** $\rightarrow$ Transitions status to `IN_PREPARATION`.
  - Click **"Mark Ready"** $\rightarrow$ Transitions status to `READY`.
  - Click **"Mark Served"** $\rightarrow$ Transitions status to `SERVED`.

## 7. Billing, Settlement & Thermal Receipt Operations

### 7.1 Generating Customer Bills (`POST /api/pos/orders/:id/bill`)
- Can be performed from the POS terminal or the **Orders & Bills** screen (`/dashboard/orders`).
- Freezes order items and produces an official bill number (e.g., `BILL-0001`).
- Table transitions to `BILLED`.

### 7.2 Processing Payments (`POST /api/pos/orders/:id/payment`)
- Supports two primary payment methods:
  - **CASH:**
    - Cashier enters tendered amount (e.g., `$50.00`).
    - Backend validates that tendered $\ge$ total payable.
    - Computes exact change to return (e.g., `$9.85`).
    - Automatically credits the active cashier's shift expected cash balance.
  - **CARD:**
    - Records card transaction reference and optional last-4 card digits.
- Generates official receipt number (e.g., `RCP-00001`).
- Automatically frees the dining table back to `AVAILABLE`.

### 7.3 Thermal Print Ready Receipts
- Both POS settlement modal and Orders Registry provide a **"Print Thermal Receipt"** action.
- Uses dedicated `@media print` CSS formatted for 80mm / 3-inch standard ESC/POS thermal receipt printers.
- Includes business name, address, tax ID, bill number, line item list, tax breakdown, and cashier signature line.

## 8. Order Voiding & Cancellation Operations

- Accessible to authorized staff on active orders.
- Prompts for a mandatory cancellation reason (e.g., "Customer walked out", "Incorrect order entry").
- Order is marked `CANCELLED`.
- Any linked dining table is immediately released back to `AVAILABLE`.
- Recorded in the system audit log and cancellation reports for managerial review.

## 9. Executive Dashboard Telemetry (`/dashboard`)

- **Telemetry Metric Cards (Pure SQL Aggregations):**
  - **Today's Revenue:** Sum of all completed payments today.
  - **Total Orders:** Count of orders processed today.
  - **Active Tables:** Live count of occupied and billed tables vs total capacity.
  - **Average Ticket Value (AOV):** Mean bill total for the day.
- **Floor Occupancy Matrix:** Live visual badges of all tables.
- **Top Performing Dishes:** Top products ranked by quantity sold and gross sales.
- **Recent Orders Table:** Live chronological stream of orders with real-time statuses.

## 10. Financial & Business Intelligence Reports (`/dashboard/reports`)

Four dedicated financial tabs with custom date-range filters:

1. **Daily Sales Performance:**
   - Breakdown by date: Total orders, gross subtotal, taxes collected, and net revenue.
2. **Payment Reconciliation Breakdown:**
   - Total volume and amounts segmented by method (Cash vs Card).
   - Instant verification of physical cash vs electronic payments.
3. **Item Sales & Menu Popularity:**
   - Product-level sales volume, unit pricing, and revenue share.
   - Highlights bestsellers and low-velocity items.
4. **Order Cancellations Audit:**
   - Chronological log of voided orders with timestamps, dollar amounts, and staff-entered cancellation reasons.

## 11. Property Configuration & Staff RBAC (`/dashboard/settings`)

### 11.1 Property Settings Tab
- Live modification of business name, physical address, email, and phone.
- Configurable base currency code (USD, EUR, THB, GBP, etc.).
- Default tax rate percentage and optional hospitality service charge.

### 11.2 Staff Accounts & Access Control Tab
- Complete staff roster with usernames, roles, and creation dates.
- Modal to provision new employee accounts with role assignment:
  - `MANAGER`: Operations manager.
  - `CASHIER`: Sales and billing cashier.
  - `KITCHEN`: Line cook / kitchen display user.
- One-click account activation/deactivation switch (guards prevent self-deactivation).

### 11.3 Immutable Security Audit Log Tab
- Real-time audit stream of security-relevant operations:
  - Account registrations
  - Property updates
  - Staff onboarding
  - Order cancellations
- Search filter by action, user ID, or affected entity.
